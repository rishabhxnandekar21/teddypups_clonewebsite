# Homepage & Scroll-Driven Interactions — Reference Fidelity Implementation

## Objective

Recreate the interactive behaviour and visual details shown in the five supplied TeddyPups reference screenshots.

Reference website: https://puppy.instabizweb.com/

This task focuses on:
- Homepage hero section.
- Puppy showcase and animated doors.
- Scroll-driven horizontal storytelling.
- Mouse-responsive airplane animation.
- Section background transitions.
- Animated footer puppy and basket.

**Important:** The live reference website is the source of truth. Do not approximate interactions with generic CSS animations. Inspect the reference behaviour first, then reproduce it in the local project.

## 1. Homepage Hero — Background, Puppy Tiles & Scalloped Bottom

Reference screenshot 1.

### Background
- Recreate the warm cream/light peach gradient.
- The centre of the hero should have a more prominent, soft peach glow.
- The outer edges should remain lighter.
- Avoid a flat, single-colour background.

### Puppy tiles
- Reproduce the arched puppy photo tiles emerging from the bottom of the hero.
- Each tile should have the correct rounded arch shape, border, image crop and positioning.
- Tiles should have a subtle recurring pop-up animation approximately every 2 seconds, matching the reference timing.
- Avoid making every tile move simultaneously if the reference uses staggered timing.
- When the cursor hovers over a tile, display the corresponding puppy's name in a small decorative label.
- The label should appear with a natural pop/bounce animation and disappear when the cursor leaves.
- Use the actual puppy names and images from the existing project data.

### Centre mascot
- Preserve the central puppy mascot and reproduce its position, scale and animation as seen in the reference.

### Bottom scalloped section
- Recreate the distinctive repeating scalloped/curved hem at the bottom of the hero.
- Match its outline, layered appearance and cream patterned section underneath.
- Ensure the puppy tiles visually emerge from behind this scalloped boundary.

## 2. Puppy Showcase — Horizontal Scroll and 3D Doors

Reference screenshot 2.

This is a critical interaction and must be investigated carefully.

### Initial appearance
- Reproduce the horizontal row of arched wooden puppy doors.
- Each door should contain its corresponding puppy image.
- Match the wooden floor, door frames, labels, typography and overall composition.
- Preserve the existing puppy inventory and navigation.

### Scroll-driven horizontal movement
- When the user scrolls vertically through this section using the mouse wheel, the content should move horizontally.
- Map vertical scroll progress to horizontal track movement.
- The transition should feel smooth and deliberate, not like an abrupt carousel jump.
- The section should remain pinned/sticky for the appropriate duration while its horizontal content moves.
- Release the page back into normal vertical scrolling when the horizontal sequence is complete.

### Door animation
- Doors should gradually open and close based on scroll progress and the user's mouse movement, following the reference behaviour.
- Reproduce the 3D perspective, hinge/pivot, rotation, depth and easing.
- Avoid simply triggering a full door-opening animation on hover.
- The opening amount should respond continuously and naturally to the relevant interaction.
- Keep the puppy images visible and correctly layered as doors move.

### Puppy mascot movement
- The mascot's horizontal position should change according to scroll direction:
  - Scrolling down: move towards the right.
  - Scrolling up: move towards the left.
- Movement should be smooth and connected to scroll progress.
- Avoid independent looping movement that does not respond to the user's input.

## 6. Technical Implementation Requirements

Before implementation:

1. Inspect the live reference at a desktop viewport of 1440×900.
2. Record the actual interaction sequence, animation timing, trigger conditions and scroll behaviour.
3. Inspect the current local implementation and identify what already exists.
4. Reuse existing components, assets, styles and animation utilities wherever possible.
5. Avoid duplicating components or creating competing animation systems.

Implementation requirements:

- Use the existing React and JavaScript architecture.
- Prefer CSS transforms and scroll-progress-driven animation over expensive layout changes.
- Use requestAnimationFrame or an equivalent efficient mechanism where continuous pointer/scroll tracking is necessary.
- Clean up event listeners and animation frames on component unmount.
- Prevent scroll trapping and ensure normal scrolling resumes after each horizontal section.
- Keep interactions responsive without unnecessary React re-renders.
- Respect prefers-reduced-motion.
- Do not introduce unnecessary animation libraries.
- Do not replace existing assets with unrelated stock illustrations.
- Do not change the puppy inventory, routes, copy or existing functionality unless necessary for fidelity.
